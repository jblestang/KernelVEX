## 1. Root Cause Analysis (Systems / Containers & Git Internals)

- **Host UID `1001` vs Container UID `10001` under rootful Docker on `ubuntu-24.04`**:
  - [verify_full_linux.sh](file:///Users/jean-baptiste/KernelVEX/scripts/verify_full_linux.sh) ran `git clone --bare --filter=blob:none` on the runner host (`uid=1001`, mode `0755`) and only ran non-recursive `chmod 0777` on `${CACHE_HOST}` and `${OUT_HOST}`.
  - Inside Docker without `--userns=keep-id`, user `10001` (`kernelvex`) could not register a worktree inside `/sources/linux-cip.git` (`Permission denied`), falling back to `git clone --shared --no-checkout` in `_prepare_isolated_checkout()`.
  - Because `git clone --shared` replaces `origin` with the local source path and omits `remote.<name>.promisor=true` / `remote.<name>.partialclonefilter`, `git checkout --detach <sha>` could not lazily fetch missing blobs from upstream (`unable to read sha1 file`), yet exited `0` leaving tracked files deleted (`D Makefile`, missing `arch/`), leading `kernelvex` / `cve-triage` to fail with exit `20`.
- **Secondary `actions/cache@v4` hazard on warm runs**:
  - Restored cache subdirectories (`cache/` and `sources/`) inherit `uid=1001`, and unconditional assertions `cold_report["meta"]["kmax_cache_hit"] is False` fail on subsequent runs once `.kmax` files are cached.
